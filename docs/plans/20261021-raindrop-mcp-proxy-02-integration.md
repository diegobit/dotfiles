# Work Unit 02: deployment and harness wiring

Status: `todo`
Depends on: 01
Design: [Raindrop MCP Worker](20261021-raindrop-mcp-proxy-00-design.md)

## Deliverable

The Worker live at `https://raindrop-mcp.diegobit.com/mcp`, four harnesses pointing at it, and `docs/mcp-setup.md` describing the new wiring. No per-machine install; Codex uses the native transport when the probe proves it works, and the documented bridge otherwise.

## Detailed Specifications

0. **Prerequisites** (stop and report if any is missing; do not invent a replacement):
   - `gh auth status` shows `diegobit`; `~/.config/.wrangler` exists and targets the account that owns `diegobit.com`; the `raindrop-mcp` hostname is free in that zone; Node 24; `~/code/raindrop-rss/config/raindrop-token` exists with mode 600.
   - `MCP_TOKEN` is generated by the implementer with `openssl rand -hex 32`. Nothing here needs the user.

1. **Deploy:**
   - `npm run check:bundle` must not create routes or secrets; confirm the dry run output.
   - Generate the production config first (`npm run config -- --profile production` or the path `npm run deploy` prints), then upload secrets against **that** config: `wrangler secret put RAINDROP_TOKEN -c <generated-config>` and the same for `MCP_TOKEN` with a freshly generated 32-byte hex value. A bare `wrangler secret put` does not discover `wrangler.base.jsonc` and can target the wrong Worker.
   - `npm run deploy:production`, then `curl` the custom domain: `initialize`, `tools/list` (six names), and one `tools/call` to `find_collections`. Confirm `Cache-Control: no-store`, `401` without a bearer, and `429` past the binding.
   - **CPU gate before any harness changes:** exercise the synthetic payloads from the design and read invocation CPU from Workers Logs, not `wrangler tail` duration. The target plan is Free (10 ms); if invocations exceed it systematically, **stop and report the measurements** instead of changing plan or caps unilaterally.
   - Cloudflare Access is not enabled: it would require service tokens for every client. The bearer model mirrors `icloud-mail-proxy`.

2. **Client token on the machines:**
   - Write the `MCP_TOKEN` value to `~/.raindrop-mcp-token`, mode 600, on the Linux machine and on the Mac. It is not the Raindrop token and never goes into a repository.
   - **Keep `~/.raindrop-token` on disk** until the Worker is verified on every harness. Worker secrets are write-only, so a rollback would otherwise have no account token to send. Delete it only after the fallback is no longer plausible.
   - `docs/mcp-setup.md` gains the new file and drops `~/.raindrop-token` from the harness section while keeping it in the rollback note.

3. **OpenCode:**
   - Remote entry, `oauth: false`, header `Authorization: Bearer {file:~/.raindrop-mcp-token}`, URL `https://raindrop-mcp.diegobit.com/mcp`.
   - Same entry in `~/.config/opencode/opencode.json` on Linux and in the repository `opencode.jsonc` for the Mac.
   - Keep the deny rules for `delete_collections` and `delete_tags` as a backstop; the Worker never exposes them.

4. **Claude Code:**
   - `claude mcp remove raindrop -s user`, then
     `claude mcp add --scope user --transport http raindrop https://raindrop-mcp.diegobit.com/mcp --header "Authorization: Bearer $(cat ~/.raindrop-mcp-token)"`.
   - Keep the existing `mcp__raindrop__delete_*` deny entries.

5. **Codex:**
   - **Probe first, with no config edit.** Codex accepts per-invocation overrides, so the probe adds a temporary server name for one process and leaves `~/.codex/config.toml` untouched:
     `codex exec -c 'mcp_servers.raindrop_probe.url="https://raindrop-mcp.diegobit.com/mcp"' -c 'mcp_servers.raindrop_probe.http_headers.Authorization="Bearer <token>"' "call raindrop_probe find_collections and reply with the titles"`.
   - This can be delegated to a subagent: it runs against the real `~/.codex` config, which is what makes the test meaningful, and the override exists only in that process.
   - If it passes, use the native form in `~/.codex/config.toml`: `[mcp_servers.raindrop]` with `url = "https://raindrop-mcp.diegobit.com/mcp"` and `http_headers = { Authorization = "Bearer <token>" }`.
   - If it fails, keep `npx -y mcp-remote <url> --header "Authorization: Bearer <token>" --transport http-only` and record which one was needed in `docs/mcp-setup.md`. Native is the target, the bridge is the documented fallback; do not assume either without the probe.
   - Either way, remove the current `mcp-remote` entry pointing at `api.raindrop.io` only after the replacement answers.

6. **Antigravity:**
   - `agy mcp remove raindrop`, then `agy mcp add --header "Authorization: Bearer $(cat ~/.raindrop-mcp-token)" raindrop https://raindrop-mcp.diegobit.com/mcp`.
   - Verification is deferred: the Antigravity CLI quota is exhausted until roughly 25 October. Mark it pending; do not claim it works.

7. **Documentation (`docs/mcp-setup.md`):**
   - Rewrite the Raindrop section: one URL, two secrets with distinct roles, the six tools and their limits, keyword `query` with Raindrop operators, saved text through the official server, Trash-only deletion, no semantic or page-body search.
   - Drop the `raindrop-mcp` local command, the Python path, and the `mcp-remote` paragraph if the native form worked.
   - Point to `~/code/raindrop-mcp/DEPLOY.md` for deployment and secrets.

8. **Verification per harness** (a configuration line is not proof; a completed turn is):
   - `curl` assertions from step 1 pass.
   - OpenCode: `opencode mcp list` shows `connected`; one turn calling `find_bookmarks` with `query`, then `fetch_bookmark_content` on a returned id.
   - Claude Code: `claude mcp get raindrop` shows the URL; one turn doing the same two calls.
   - Codex: `codex mcp get raindrop` shows the chosen transport; one non-interactive turn doing the same two calls.
   - Antigravity: `agy mcp list` shows the entry; a turn deferred until the quota resets.
   - In each harness, confirm the six names are present and `delete_collections`/`delete_tags` are absent.

9. **Rollback:**
   - Point the four harnesses back at `https://api.raindrop.io/rest/v2/ai/mcp` with the account token, restoring `mcp-remote` for Codex only.
   - The Worker can stay deployed and unused; no data lives in it. No commented-out duplicates in the configs.

## Acceptance

- The Worker answers six tools at the custom domain over HTTPS with the bearer, and `401` without it.
- Three harnesses verified by a completed turn, including one `query` search and one content fetch; Antigravity recorded as pending.
- No token in any tracked file; `~/.raindrop-mcp-token` is the only client secret on each machine.
